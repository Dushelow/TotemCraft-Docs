# TotemAuthMeAddon

Аддон TotemCraft к AuthMe 6.0.1 (оригинальный AuthMe, сборка Paper). Сервер: Paper/Purpur 26.3.

## Механики

### Жемчуг Края при входе не пропадает (`keep-ender-pearls-on-join`)

Проблема (найдена 14.11.2026, в журнале «Failed to spawn player ender pearl in level ..., skipping»):
с 1.21.2 игра при выходе убирает брошенный жемчуг игрока в его сохранение, а при входе возвращает в мир.
Paper считает возвращение запуском снаряда (`ProjectileLaunchEvent`). Игрок в этот момент ещё не ввёл
пароль, и AuthMe (`EntityListener.onProjectileLaunch`, LOWEST) отменяет запуск. Жемчуг из стазис-камеры
не возвращается; после входа AuthMe воссоздаёт его по снимку при выходе (`limbo.recreateEnderPearls`),
и такой жемчуг может сразу сработать и перенести игрока. Тестовая AuthMe 6.0.2-SNAPSHOT (ноябрь 2026) этого
не исправляет.

Исправление: на `ProjectileLaunchEvent` с приоритетом HIGHEST разрешаем обратно только жемчуг, у которого
хозяин ещё не вошёл по паролю и который не новый (`getTicksLived() > 0`: возвращённый из сохранения хранит
возраст, только что брошенный - 0). Бросить жемчуг до ввода пароля нельзя: AuthMe запрещает предметы. После
входа AuthMe находит жемчуг по UUID и только заново привязывает его к игроку.

`log: true` - каждый возвращённый жемчуг пишется в журнал (кто и где).

## Сборка

`lib/authme.jar` скопировать с сервера (`AuthMe-6.0.1-Paper.jar`), затем
`mvn -q -B package` (или через Docker, как у остальных плагинов). Jar: `target/TotemAuthMeAddon-<версия>.jar`.

## Проверка на стенде

`testbed/bot/pearl_relog.js 1` (робот вешает свой жемчуг, выходит), затем `pearl_relog.js 2` (входит снова).
Без аддона: жемчуг пропадает, «Failed to spawn», робот переносится к жемчугу. С аддоном: жемчуг на месте.
Окно входа AuthMe на время теста выключить (строки 355 и 373 config.yml), потом вернуть.
