# Telegram‑бот для вайтлиста и заявок Minecraft‑сервера TotemCraft

## 1. Введение

Бот предназначен для автоматизации приёма заявок на регистрацию (вайтлист), обработки обращений игроков, управления тикетами и интеграции с игровым сервером Minecraft (Purpur + AuthMe). Реализован на Python с использованием библиотеки `pyTelegramBotAPI`.

**Ключевые возможности:**
- Подача заявок с валидацией ника и пароля по правилам AuthMe.
- 24‑часовой таймер повторной подачи заявки.
- Полная история заявок в CSV.
- Система тикетов и диалогов «админ ↔ игрок».
- Уведомления в Discord о новых заявках, решениях, обращениях, блокировках.
- Автоматическая регистрация аккаунта на сервере через RCON‑команду `authme register` (пароль не попадает в Discord).
- Административная панель с инлайн‑кнопками (просмотр заявок, ответы, статистика, управление).
- Ежедневное напоминание о нерассмотренных заявках.

## 3. Установка и запуск

### 3.1 Переменные окружения

Бот ожидает следующие переменные (обязательные):

```bash
BOT_TOKEN=ваш_токен_бота
ADMIN_ID=123456789               # числовой ID администратора
DISCORD_WEBHOOK_URL=https://...  # URL вебхука Discord для уведомлений
CONSOLE_WEBHOOK_URL=https://...  # вебхук канала консоли Discord: туда дублируется команда регистрации с паролем звёздочками
RCON_PASSWORD=...                # пароль RCON из server.properties (rcon.password)
RCON_HOST=127.0.0.1              # необязательно, по умолчанию 127.0.0.1
RCON_PORT=25575                  # необязательно, по умолчанию 25575
MC_SERVER_DIR=/home/minecraft/server  # необязательно: откуда читать баны и AuthMe
DEFAULT_TZ=Europe/Moscow         # необязательно: пояс показа времени по умолчанию
LEGACY_TZ=Europe/Moscow          # необязательно: в каком поясе записаны старые файлы (для разового переноса)
```

**Рекомендация:** для production использовать `EnvironmentFile` в systemd.

### 3.2 Зависимости

Установка через pip:

```bash
pip install pyTelegramBotAPI requests schedule pytz python-dotenv
```

### 3.3 Запуск

Скрипт `bot.py` сам запускает поллинг и планировщик в отдельном потоке:

```bash
python3 bot.py
```

**systemd‑сервис (пример):**

```ini
[Unit]
Description=TotemCraft Telegram Bot
After=network.target

[Service]
Type=simple
User=minecraft
WorkingDirectory=/home/minecraft/bot
EnvironmentFile=/home/minecraft/bot/.env
ExecStart=/usr/bin/python3 /home/minecraft/bot/bot.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

## 4. Архитектура и данные

### 4.1 Файлы бота

```
bot.py            — запуск и все обработчики Telegram (меню, заявки, обращения, команда, журнал)
tcbot/config.py   — переменные окружения и константы
tcbot/storage.py  — база bot.db: схема и её версии, перенос старых файлов, запись, копии
tcbot/timeutil.py — время: хранение в UTC, показ в поясе человека, список поясов
tcbot/bans.py     — поиск наказаний на сервере (AdvancedBanX, ванильные списки, AuthMe)
tcbot/tgage.py    — примерная дата регистрации аккаунта Telegram по ID
tcbot/mmdb.py     — страна по IP из базы GeoLite (формат MaxMind), без сторонних библиотек
tcbot/autoaccept.py — правила автопринятия заявок
tcbot/badwords.py — словарь: мат, оскорбления, символика, политика
tcbot/rcon.py     — RCON: команда в консоль сервера
tcbot/logs.py     — журнал ошибок с ограничением размера
tcbot/i18n.py     — тексты для игроков на русском, украинском и английском, справочник «О сервере», описание бота
tests/            — тесты с поддельными Telegram, Discord и RCON
```

Рядом с `bot.py` на сервере бот сам создаёт: `bot.db` (+ `bot.db-wal`, `bot.db-shm`), `backups/` (копия базы каждый день в 04:00 МСК, 14 последних, и разовая `bot-before-vN.db` перед обновлением схемы), `legacy_files/` (старые JSON/CSV после переноса, не удаляются), `bot_errors.log`.

### 4.2 База `bot.db`

Все даты — строки ISO 8601 в UTC (`2026-09-19T13:40:00+00:00`). Показ человеку — в его поясе: у члена команды свой пояс (⚙️ Управление → 🕐 Мой часовой пояс), у остальных `DEFAULT_TZ`.

| Таблица | Что хранит |
|---|---|
| `meta` | версия схемы (`schema_version`) |
| `applications` | история решений по заявкам: подана, решена, TG ID, username, ник, статус, комментарии, кто рассмотрел. Паролей нет |
| `messages` | вся переписка с игроками (без ограничения в 20 сообщений), кто из команды писал |
| `kv` | маленькие наборы: `pending` (очередь заявок, здесь пароль до решения), `tickets`, `last_application`, `blocked`, `unread`, `dialogs` (диалоги переживают перезапуск), `lang` (язык игрока: `ru`, `uk`, `en`), `settings` (пауза, счётчик тикетов) |
| `staff` | команда: роль, кто и когда добавил, пояс |
| `audit` | журнал действий |
| `notices` | какие уведомления у кого, чтобы дописать итог |

Схема обновляется сама при запуске (`storage.migrate()`): каждая версия в одной транзакции, при ошибке база остаётся прежней. Версия 2 один раз переносит старые файлы (`pending.json`, `approved_applications.csv`, `chat_history.json` и др.), переводя время из `LEGACY_TZ` в UTC, и откладывает их в `legacy_files/`.

Выгрузка истории заявок для Excel: ⚙️ Управление → 📤 Выгрузить историю заявок (владелец). Разделитель `;`, время в UTC.

### 4.3 Тесты

```bash
pip install pyTelegramBotAPI requests schedule pytz
python tests/run_tests.py
```

`test_migration.py` — перенос старых файлов и базы версии 1; `test_scenarios.py` — заявки, команда, обращения, журнал, пояса, режим игрока, баны, досье, выгрузка, копия базы; `test_edge.py` — нестандартные случаи: ошибки ввода, опасные символы и очень длинные тексты, игрок заблокировал бота, сервер недоступен и повтор регистрации, перезапуск посреди диалога, испорченные кнопки, 8 потоков одновременно, ограничитель частоты; `test_load.py` — база в 10 раз больше боевой, порог 300 мс на экран; `test_lang.py` — выбор языка, анкета, обращение и одобрение на украинском и английском, полнота переводов. Настоящие Telegram, Discord и сервер не трогаются: поддельный Telegram отвечает ошибками как настоящий (пустой текст, битая разметка, длина больше 4096, «message is not modified»).

Проверка на живом сервере (RCON, баны AdvancedBanX и база AuthMe, пока сервер их пишет): `testbed/bot_live_check.py`, порядок в `testbed/README.md`.

Любая ошибка в обработчике не роняет его молча: нажавший получает «Кнопка устарела» или «Что-то пошло не так», ошибка идёт в `bot_errors.log` (испорченные данные кнопки — как предупреждение).

### 4.4 Поток управления

Бот работает в двух параллельных потоках:
1. **Основной** – `bot.infinity_polling()` обрабатывает сообщения и колбэки.
2. **Планировщик** – `run_scheduler()` каждую минуту проверяет расписание: напоминание о заявках в 08:00 МСК, копия базы в 04:00 МСК.

## 5. Модули и ключевые функции

### 5.1 Валидация (AuthMe‑совместимая)

```python
def validate_nick_authme(nick: str) -> tuple[bool, str]
```
- Длина 3–16 символов.
- Разрешены: `A-Z a-z 0-9 _`.
- Возвращает `(True, '')` или `(False, причина)`.

```python
def validate_password_authme(password: str, nick: str = None) -> tuple[bool, str]
```
- Длина 6–30, без пробелов, без кириллицы.
- Не должен совпадать с ником (регистронезависимо).
- Чёрный список слабых паролей (`WEAK_PASSWORDS`).
- Запрещены: только цифры, простые последовательности (`1234`, `abcd`), повторяющиеся блоки (`abcabc`).

### 5.2 Работа с данными

- `load_json(filename, default)` / `save_json(filename, data)`
- `read_approved_csv()` – возвращает список строк (без заголовка)
- `check_nick_already_approved(nick)` – проверка, не занят ли ник (только одобренные)
- `check_duplicate_tg_id(tg_id)` – проверяет, подавал ли этот TG ID заявку ранее (из CSV)
- `reload_pending()` – перечитывает очередь заявок из базы (используется перед напоминанием)

### 5.3 Отправка команд на сервер Minecraft

```python
def rcon_command(command: str) -> str
def register_on_server(nick: str, password: str) -> None
def send_console_command(command: str) -> None
```
`rcon_command` выполняет команду в консоли сервера по RCON (`RCON_HOST`, `RCON_PORT`, `RCON_PASSWORD`).  
`register_on_server` регистрирует аккаунт командой `authme register` через RCON и дублирует в канал консоли Discord строку `authme register <ник> ********`. Если сервер недоступен, админ получает сообщение с кнопкой «🔁 Повторить регистрацию» (пароль для повтора хранится только в памяти до перезапуска бота).  
`send_console_command` только пишет строку в канал консоли Discord через `CONSOLE_WEBHOOK_URL`. DiscordSRV не выполняет сообщения вебхуков, поэтому команду через него отдать нельзя.

Медленные вызовы (вебхуки Discord, картинка и сообщение игроку о решении, RCON) идут в фоне через `run_in_background`, чтобы кнопки отвечали сразу.

### 5.4 Интеграция с Discord

Все функции `discord_*` формируют embed и отправляют на `DISCORD_WEBHOOK_URL`.  
**События:**
- Новая заявка (плюс прошлые ники этого TG ID, число найденных блокировок, пометка тестовой)
- Решение (одобрено/отклонено, «Рассмотрел: имя»)
- Обращение игрока (тикет)
- Сообщение гостя
- Блокировка игрока («Заблокировал: имя»)
- Открытие/закрытие диалога («Администратор: имя»)
- Отмена заявки игроком
- Изменение команды (выдан доступ, сменена роль, снят доступ)
- Ежедневное напоминание о pending заявках

Имена членов команды в Discord видны: канал уведомлений рассчитан только на команду.

### 5.5 Rate limiting

```python
RATE_LIMIT = 5          # сообщений
RATE_WINDOW = 5         # секунд
RATE_COOLDOWN = 10      # секунд блокировки после превышения
```
Для администратора ограничение не действует. При срабатывании пользователю отправляется предупреждение и временная блокировка ввода.

## 6. Система заявок (вайтлист)

### 6.0 Язык игрока

Игрок видит бота на русском, украинском или английском.
- При первом `/start` бот сам берёт язык из языка приложения Telegram (`language_code`): русский — русский, украинский — украинский, всё остальное — английский как международный (`i18n.BY_CLIENT`). Гадать по соседним языкам не стали: язык человек выбрал себе сам, а сменить его в боте одна кнопка. Выбор сохраняется в базе (`kv`, раздел `lang`).
- Исключение: у кого уже есть заявка или переписка в базе, тот остаётся на русском, даже если приложение английское. Давний игрок мог поставить английский интерфейс, а говорить по-русски.
- Сменить язык: кнопка в главном меню с флагом текущего языка («🇷🇺 Русский»), за ней три кнопки с флагами.
- Кто язык не получил (нажал кнопку в старом сообщении, не открыв бота заново), видит русский.
- Переведено всё, что видит игрок: меню, анкета, ошибки ника и пароля, правила, ответы о заявке, обращения, справочник «О сервере». Админка, журнал и Discord на русском. Ответы админов в диалоге приходят как написаны, подпись «Сообщение от администрации» на языке игрока.
- Нижние кнопки бот узнаёт по тексту на любом из трёх языков.
- Поправить перевод: `tcbot/i18n.py`, слова в `{скобках}` не трогать. После правки `python tests/run_tests.py`: `test_lang.py` проверит, что у каждой строки есть три языка и подстановки совпадают.

Описание бота до кнопки START Telegram показывает по языку приложения. Русское задаётся в BotFather и видно всем, кроме украинского и английского приложения. Украинское и английское бот ставит сам при каждом запуске (`DESCRIPTION` и `SHORT_DESCRIPTION` в `tcbot/i18n.py`); если Telegram откажет, бот работает дальше и пишет предупреждение в `bot_errors.log`.

### 6.1 Процесс подачи (со стороны пользователя)

1. Пользователь нажимает кнопку **«📝 Подать заявку на сервер»** (инлайн‑кнопка в главном меню).
2. Проверки: регистрация не приостановлена, пользователь не заблокирован, нет активной заявки в `pending`, не прошло 24 часа с предыдущей заявки.
3. Состояние `user_states[uid] = {'step': 'nick'}`.
4. Пользователь вводит ник → валидация → сохранение → переход к `step: 'password'`.
5. Ввод пароля → валидация → переход к `step: 'comment'`.
6. Комментарий (можно пропустить кнопкой) → показ подтверждения (инлайн‑кнопки «Подтвердить» / «Отмена»).
7. После подтверждения → показ правил сервера с кнопками «Согласен» / «Не согласен».
8. При согласии: заявка сохраняется в очередь `pending` (база), фиксируется `last_application[uid] = now` (UTC), уведомление админу и Discord.

### 6.2 Обработка заявки администратором

- Админ открывает панель → «📋 Заявки» → постраничный просмотр.
- Для каждой заявки доступны кнопки: **✅ Одобрить**, **❌ Отклонить**, **🚫 Заблокировать**, **💬 Ответить**.
- При одобрении/отклонении:
  - Админу предлагается ввести комментарий (или пропустить). Комментарий сохраняется в CSV.
  - Заявка удаляется из `pending`, добавляется в таблицу `applications` со статусом и тем, кто рассмотрел (пароля там нет).
  - Если действие = `approve` – аккаунт регистрируется через `register_on_server` (RCON). «Отмена» при вводе комментария регистрацию не запускает.
  - Пользователь получает уведомление (при одобрении – пароль и IP сервера).
  - Отправляется embed в Discord.

### 6.3 Ограничения и защита

- **24 часа** между заявками от одного TG ID (хранится в `last_application.json`).
- Проверка уникальности ника (только среди **одобренных** заявок).
- Проверка, что TG ID ранее не подавал заявку (предупреждение админу, но не блокирует). В карточке перечислены прошлые ники этого TG ID.
- При приостановке регистрации (`/pause` или кнопка в админ‑панели) новые заявки не принимаются.

### 6.4 Проверка блокировок

В уведомлении о новой заявке и в карточке заявки бот показывает блок «🚨 Блокировки», если у игрока есть наказания. Проверяются ник заявки и все прошлые ники этого TG ID. Бот только читает файлы сервера (`MC_SERVER_DIR`, по умолчанию `/home/minecraft/server`), ничего не меняет:

| Источник | Файл | Что там |
|---|---|---|
| AdvancedBanX | `plugins/AdvancedBanX/data/storage.script` + `storage.log` (база HSQLDB, текст) | `/ban`, `/tempban`, `/ipban`, `/mute`, `/warn`, баны Vulcan |
| Ванильный список | `banned-players.json`, `banned-ips.json` | `/minecraft:ban`, Essentials; AdvancedBanX копирует сюда свои баны |
| AuthMe | `plugins/AuthMe/authme.db` (столбцы `ip`, `regip`) | IP прошлых ников, чтобы найти баны по IP |

- Показываются только действующие наказания: тип, срок, причина, кто выдал, когда и где найдено. Одинаковые записи из AdvancedBanX и ванильного списка склеиваются.
- Снятые и истёкшие наказания одной строкой «Раньше: …» (кики и заметки не считаются).
- Если ничего не найдено, блока нет.
- Если источник не прочитался, бот не падает: в блоке строка «⚠️ Не удалось проверить …», ошибка в `bot_errors.log`, остальные источники проверяются.
- `/check` AdvancedBanX через RCON не подходит: плагин отвечает асинхронно, ответ до RCON не доходит.

### 6.5 Досье игрока и проверки

Блок «🧾 Досье» в уведомлении о новой заявке (кратко), в карточке заявки и в профиле игрока:

- **📱 Telegram**: примерная дата регистрации по ID («≈ май 2025 (около года)»), Premium, есть ли фото и username, язык приложения. Telegram не отдаёт ботам ни точную дату регистрации, ни страну, ни номер. Дата оценивается по опорным точкам `tcbot/tgage.py`: открытый набор github.com/jobians/telegram-id-age (MIT) до 2025 года, сглаженный, плюс самые свежие ID заявителей бота по месяцам (пополняется из базы само). Проверка на открытом наборе: медианная ошибка 1,6 месяца, в 80% случаев до 3 месяцев. Фото, Premium и язык снимаются в момент подачи заявки.
- **🎮 Сервер**: для ника заявки и прошлых ников этого TG ID из AuthMe: дата регистрации, последний вход, страна по IP (база `plugins/AuthMe/GeoLite2-Country.mmdb`, читается `tcbot/mmdb.py` без сторонних библиотек).
- **👥 С того же IP** (карточка и профиль): другие аккаунты AuthMe с тем же IP (последним или при регистрации).

Проверки (только сильные сигналы, иначе одна строка «✅ Проверки пройдены»):

| Уровень | Когда |
|---|---|
| 🔴 | действующий бан на нике, прошлом нике или по IP |
| 🔴 | с того же IP есть аккаунты в бане |
| 🔴 | TG ID заблокирован в боте |
| 🟡 | раньше отклоняли заявки этого TG ID |
| 🟡 | «совсем новый» аккаунт Telegram: ID новее всех, кто подавал заявки больше 30 дней назад (плюс пометка «без фото и username», если так) |

Рейд: если за час пришло 5 и больше заявок от «совсем новых» аккаунтов, включается рейд-режим (6.7). В Discord в новую заявку попадают только 🔴.

Пороги в начале блока «Досье игрока и проверки» в `bot.py`: `VERY_NEW_DAYS`, `RAID_WINDOW_MIN`, `RAID_COUNT`.

### 6.6 Автопринятие заявок

Включается владельцем: ⚙️ Управление → 🤖 Автопринятие и рейды (по умолчанию выключено). Правила в `tcbot/autoaccept.py`, словарь в `tcbot/badwords.py`. Игрок ничего из этого не видит: для него всё как раньше. Команда видит вердикт в уведомлении и карточке заявки, Discord — в новой заявке («Автомат: …»).

| Вердикт | Когда | Автопринятие |
|---|---|---|
| ⚡ | без мелочей и подписан на группу `SUBSCRIBE_CHAT` (по умолчанию @totemcraftnet, бот должен быть её админом) | через 5 минут |
| 🟢 | без мелочей | через 1 час |
| 🟡 | 1 мелочь | через 12 часов |
| 🟠 | 2 мелочи / 3 и больше | через 24 / 48 часов |
| ✋ | хотя бы один стоп-фактор | только вручную |

Срок считается от подачи заявки. Мелочи: нет аватарки, нет username, Telegram моложе года, есть комментарий, 6+ цифр подряд в нике. Стоп-факторы: бан или мут когда-либо (ник, прошлые ники этого TG ID, по IP), твинк (у TG ID уже был одобренный аккаунт или с того же IP есть аккаунт в бане), блок в боте, брань/символика/политика в нике, пароле или комментарии (встроенный словарь + свои слова владельца), раньше отклоняли, Telegram моложе 2 месяцев, игрок пытался обратиться в поддержку, пока заявка ждёт, не удалось прочитать баны.

Каждую минуту бот берёт подошедшие заявки и **перепроверяет** их (вдруг появился бан). Если стал стоп — команде сообщение «✋ Автомат не принял …». Заявку, которую сейчас решает админ, бот не трогает. Автопринятие = обычное одобрение: регистрация через RCON, сообщение игроку, в истории и журнале «🤖 автоматически», в Discord «Рассмотрел: 🤖 автоматически».

Лимит: 5 в час и 10 в сутки (скользящие окна). Сверх лимита подошедшие заявки ждут в очереди с пометкой «ждёт лимита, продолжит примерно в ЧЧ:ММ» и принимаются сами, когда место освободится; админы могут решить их раньше вручную. Команде одно сообщение в час с временем продолжения, счётчики видны в настройках и в панели («за сутки N из 10»).

Проверка на истории (1069 заявок до 19.09.2026, без данных об аватарках): автоматом прошли бы 72% (1 ч — 491, 12 ч — 257, 24 ч — 25), из них владелец отклонил 13 (1,7%), в основном за просьбы ускорить.

Словарь (`tcbot/badwords.py`): мат, оскорбления, символика (в т.ч. 1488), политика; латиница с обходами (p_i_d_o_r, P1d0r, 6lyat) и кириллица (комментарии проверяются по словам, чтобы «хочу играть» не давало ложного срабатывания); исключения для обычных слов (Technoblade, Mandarin, Lebanon). На 1069 никах 16 срабатываний, все по делу. Свои слова — «📖 Свои слова» в настройках.

### 6.5а Как выглядит заявка у команды

Уведомление о новой заявке и карточка в «📋 Заявки» короткие: ник и username, комментарий (до 200 знаков), «⚠️ Уже подавал: …» и вердикт автомата одной строкой («🟢 Автопринятие через 1 ч · в 18:40» или «✋ Вручную: причина»). Кнопки «✅ Одобрить» и «❌ Отклонить» сразу в уведомлении. «🧾 Подробнее» на месте открывает всё: имя, ID, дату, досье, проверки, баны; «🔙 Кратко» возвращает короткий вид. После решения уведомление у всех сворачивается в две строки: «📁 Заявка закрыта · ник» и «✅ ОДОБРЕНО 19.09 18:03 · кто решил» (плюс комментарий).

### 6.6а Проверка после первого входа

На момент заявки IP новичка неизвестен, поэтому игрок с баном на ник может прийти с новым ником и чистой заявкой. После одобрения (ручного или автоматического, кроме тестовых) ник записывается в набор `watch` с временем проверки через сутки (`WATCH_HOURS = 24`). Раз в час бот берёт тех, у кого сутки прошли (если таких нет, в AuthMe не ходит), одним запросом смотрит их IP в AuthMe и каждого сразу убирает из списка. Если игрок заходил: если на его IP есть бан AdvancedBanX или с этого IP заходил забаненный аккаунт, владельцу и админам (не помощникам) и в Discord уходит «🔴 Возможный твинк» с причинами и кнопкой «Профиль игрока», в журнал запись `twin_suspect`. Сам бот никого не банит. Если за сутки не заходил, просто убирается из списка.

### 6.7 Рейд-режим

По образцу AntiBot в AuthMe. Состояния: «👀 слежу» (автовключение), «🔴 активен до ЧЧ:ММ» (включился сам на 60 минут), «🔴 включён вручную» (до выключения), «⚪ автовключение выключено». Включается сам, если за 60 минут 5+ заявок от совсем новых аккаунтов Telegram. Пока активен, автопринятие ничего не принимает; в панели у команды «🛡 Рейд-режим активен». Команде и в Discord сообщение о включении и выключении, у владельца кнопка «Выключить рейд-режим». Настройки: включить сейчас, выключить, автовключение вкл/выкл.

## 7. Система тикетов и диалогов

### 7.1 Создание тикета

Пользователь нажимает **«🚨 Жалоба / вопрос администратору»** → выбирает:
- **«✅ Да, есть аккаунт»** → вводит игровой ник и текст обращения → создаётся тикет. Если вместо ника игрок сразу пишет текст (ник не проходит проверку AuthMe), бот сохраняет текст как обращение и отдельно спрашивает ник; после ника тикет создаётся без повторного вопроса.
- **«❌ Нет аккаунта»** → может подать заявку (`support_new`) или отправить сообщение как гость (`support_guest`).

Тикет сохраняется в базе (`kv`, набор `tickets`) с уникальным номером (счётчик `ticket_counter`).  
**Важно:** если у пользователя уже есть активный тикет, новый не создаётся – бот предлагает дождаться ответа.

### 7.2 Диалог между админом и пользователем

- Админ нажимает **«💬 Ответить»** в профиле пользователя или в уведомлении о новом сообщении.
- Бот присылает одно сообщение: «Вы отвечаете: ник (@username) · имя», все сообщения игрока после последнего ответа команды (до 10, обращение разбито на «Ник» и «Проблема»), пометка «⚠️ Указал другой ник», если ник в обращении не совпадает с ником из последней заявки. Кнопки: «✅ Ответил, закрыть» (завершить диалог и закрыть тикет), «🔒 Закрыть без ответа», «🚫 Заблокировать», «🏠 Меню». Панель администратора заново не присылается.
- Устанавливается `admin_reply_to = user_id`, снимается флаг непрочитанных.
- Все сообщения админа автоматически пересылаются пользователю и наоборот.
- Сохраняется история в таблице `messages` (без ограничения по числу).
- Админ может завершить диалог кнопкой **«✅ Ответил, закрыть»**, кнопкой в панели или командой `/stopreply`. Пользователь может завершить диалог кнопкой **«❌ Завершить диалог»**.
- При завершении диалога закрывается соответствующий тикет (`close_ticket`).
- **«⏸ Отойти»** (в сообщении диалога и в панели): диалог снимается, тикет остаётся открытым, игроку ничего не пишется. Текст админа после этого игроку не уходит. Вернуться: «💬 Ответить» в уведомлении или профиле.
- Если у игрока открыт тикет, а диалога нет (никто не взял или админ отошёл), его сообщения сохраняются в переписку, команде приходит уведомление «↩️ Дописал в открытое обращение» с кнопкой «Ответить», игрок видит «✉️ Добавлено к обращению #N». Кнопка игрока «❌ Завершить диалог» в этом случае закрывает обращение.

### 7.3 Непрочитанные сообщения

- Сообщение от пользователя (вне активного диалога) добавляет `user_id` в `message_queue.json` и `unread_messages` (множество).
- Админ видит количество непрочитанных в главной панели.
- Как только админ открывает диалог или просматривает историю, сообщения считаются прочитанными и удаляются из очереди.

## 8. Административная панель

### 8.1 Основная панель

Вызывается командой `/start` (или `/admin`) для члена команды. Кнопки зависят от роли (см. 8.4):

- **📋 Заявки** – постраничный просмотр `pending` с кнопками действий.
- **💬 Сообщения** – две вкладки: «Не отвеченные» (есть в очереди) и «Отвеченные». У игрока, с которым уже идёт диалог, в списке видно имя админа.
- **🔍 Поиск по нику** и **📊 Статистика** (профили пользователей списком по 10).
- **📒 Журнал** и **👥 Команда** – только у владельца.
- **⚙️ Управление** – приостановка регистрации, заблокированные, сброс таймеров, очистка, инструкция (по правам роли).
- **👤 Посмотреть как игрок** – см. 8.6.

В шапке панели: роль и имя, сколько заявок и непрочитанных, свой диалог и диалоги коллег.

### 8.2 Команды (текстовые)

| Команда                       | Кто | Действие                                                    |
|-------------------------------|-----|-------------------------------------------------------------|
| `/id`                         | все | Показать свой Telegram ID (нужен, чтобы выдать доступ)      |
| `/admin`                      | команда | Вернуться в панель (в том числе из режима игрока)       |
| `/pause`, `/resume`           | владелец | Приостановить / возобновить приём заявок               |
| `/block <user_id> [причина]`, `/unblock <user_id>` | владелец, админ | Блокировка в боте      |
| `/status`                     | команда | Регистрация, заблокированные, свой диалог и диалоги коллег |
| `/history <user_id>`          | владелец, админ | История сообщений с пользователем               |
| `/stopreply`                  | команда | Завершить свой диалог                                   |

### 8.3 Управление тикетами

- В профиле пользователя видны последние 5 сообщений, историю открывать не нужно.
- Кнопка **«🔒 Закрыть без ответа»** (в профиле и в уведомлении) закрывает тикет и убирает обращение из «Не отвеченных». Игроку приходит «Ваш тикет #N закрыт администратором».
- При нажатии «💬 Ответить» бот показывает последнее сообщение игрока.
- При закрытии тикета, если диалог активен, он также завершается.
- История сообщений не удаляется, но тикет удаляется из набора `tickets`.

### 8.4 Команда и роли

Владелец задаётся `ADMIN_ID` в `.env`, остальных добавляет владелец: **👥 Команда → ➕ Добавить**, Telegram ID человека (он узнаёт его командой `/id`), роль.

| Право | Владелец | Админ | Помощник |
|---|:-:|:-:|:-:|
| Заявки: смотреть, одобрять, отклонять | ✅ | ✅ | ✅ |
| Поиск по нику | ✅ | ✅ | ✅ |
| Сообщения, диалоги, профили игроков | ✅ | ✅ | |
| Блокировка в боте | ✅ | ✅ | |
| Статистика и профили пользователей | ✅ | ✅ | |
| Журнал, команда, пауза, сброс таймеров, очистка | ✅ | | |

- Уведомления о новых заявках получают все, об обращениях – владелец и админы.
- Кто нажал «Одобрить»/«Отклонить», тот держит заявку, пока пишет комментарий: у остальных кнопка отвечает «заявку рассматривает …».
- После решения у всех уведомление о заявке помечается «✅ ОДОБРЕНО · имя» и теряет кнопки. То же для обращений: «Отвечает: имя», «Закрыто без ответа · имя».
- У каждого админа свой диалог. Сообщения игрока приходят только тому, кто с ним в диалоге. Владелец может забрать чужой диалог, остальные получают отказ.
- Игрок всегда видит «Администрация», имя админа ему не показывается. В истории переписки (профиль, «Вся переписка», `/history`) видно, кто из команды что писал.
- Снятие доступа: карточка члена команды → «🗑 Снять доступ». Его диалог завершается, журнал его действий сохраняется.

### 8.5 Журнал действий

Таблица `audit` в `bot.db`: время, кто (член команды, игрок или бот), роль, действие, игрок (ID и ник), подробности. Пишется: подача и отзыв заявок, решения с комментарием, результат регистрации на сервере, обращения, открытие и закрытие диалогов, каждое сообщение админа игроку, закрытие без ответа, блокировки, пауза, сброс таймеров, очистки, изменения команды. Хранится бессрочно.

Просмотр (владелец): **📒 Журнал** – все действия по 8 на странице, новые сверху; **👥 По админу** – действия одного члена команды (в том числе бывшего); **🔍 По игроку** – ник или Telegram ID. Кнопка «📒 Журнал» есть и в карточке заявки, профиле игрока, карточке из истории заявок и карточке члена команды.

Если запись в журнал не удалась, действие всё равно выполняется, ошибка уходит в `bot_errors.log`.

### 8.6 Режим игрока

Кнопка **«👤 Посмотреть как игрок»**: бот показывает члену команды обычное меню игрока. Внизу есть кнопка «🛡 Вернуться в админку», которую видит только он, также работает `/admin`. Заявка из этого режима помечается тестовой: у команды «🧪 Тестовая», таймер 24 часа не ставится, при одобрении на сервере не регистрируется и в статистику не попадает. Обращения из режима игрока помечаются «🧪 Тест». Пока член команды в режиме игрока, кнопки из админских уведомлений отвечают подсказкой вернуться.

## 10. Интеграция с AuthMe

**Механизм:**  
При одобрении заявки вызывается:

```python
register_on_server(app['nick'], app['password'])
```

Команда уходит по RCON на `127.0.0.1:25575`. На сервере Minecraft в `server.properties`: `enable-rcon=true`, `rcon.password=<тот же пароль, что RCON_PASSWORD>`, `broadcast-rcon-to-ops=false`. Порт 25575 наружу не открывать (UFW его не пропускает, пока нет `ufw allow 25575`).  
AuthMe пишет в журнал `[AuthMe] Rcon registered <ник>`, пароль в журнал и в Discord не попадает. Ответ RCON на регистрацию пустой: AuthMe регистрирует асинхронно.

---

### 10.1 Bedrock-игроки (Floodgate)

Floodgate ставит Bedrock-игрокам префикс `username-prefix: "."` и обрезает имя до 16 знаков. При одобрении бот регистрирует через RCON два аккаунта с одним паролем: `ник` и `.ник` (например `.Steve`; для 16-значного ника — первые 15 знаков после точки). В канал консоли Discord уходят обе команды со звёздочками, игроку в сообщении об одобрении подсказка «С телефона или консоли (Bedrock) ваш ник: .ник, пароль тот же». Префикс задаётся `BEDROCK_PREFIX` в `.env` (по умолчанию «.», пусто — не регистрировать). Баны на `.ник` учитываются для `ник` в досье, проверках и автопринятии. Проверено на тестовом сервере: AuthMe принимает `authme register .ник` из консоли (`allowedNicknameCharacters: '[a-zA-Z0-9_.]*'`).

## 11. Обработка ошибок и логирование

- Все исключения в обработчиках и функциях отправки перехватываются и записываются в `bot_errors.log` с помощью `log_error(e)` (которая использует `traceback.format_exc()`).
- При сбое отправки сообщения (особенно с `parse_mode`) бот автоматически повторяет отправку без форматирования.
- Ошибки при отправке команд на сервер или в Discord логируются, но не прерывают работу бота.

## 12. Расширение и кастомная доработка

### 12.1 Добавление новых команд администратора

Достаточно добавить новый обработчик:

```python
@bot.message_handler(commands=['mycommand'])
def mycommand(m):
    if m.chat.id != ADMIN_ID: return
    # логика
```

### 12.2 Изменение справочника «О сервере»

Словарь `HANDBOOK_CHAPTERS` определён в коде. Можно добавить новую главу, следуя формату:

```python
'new_key': {
    'emoji': '🆕',
    'title': 'Новый раздел',
    'text': 'Текст раздела в HTML'
}
```

и добавить ключ в `CHAPTER_ORDER`.

### 12.3 Настройка времени ежедневного напоминания

Изменить строку в `run_scheduler()`:

```python
schedule.every().day.at("08:00", "Europe/Moscow").do(daily_job)
```

### 12.4 Изменение лимитов (rate limiting, 24h timer)

Переменные в начале файла:
- `RATE_LIMIT`, `RATE_WINDOW`, `RATE_COOLDOWN`
- Логика 24‑часового таймера: `if datetime.now() - last_dt < timedelta(hours=24)`

### 12.5 Поддержка дополнительных языков

Все тексты сообщений и кнопок в коде на русском языке. Для локализации потребуется вынести строки в отдельный файл или словарь.
