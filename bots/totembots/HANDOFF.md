# TotemBots без Claude: как запускать и как продолжать с другой нейросетью

## Запуск

На рабочем столе ярлык **TotemBots**: двойной щелчок, и программа открывается. Ярлык запускает
`node_modules\electron\dist\electron.exe` с папкой программы
`C:\Users\admin\claude-spaces\totemcraft_server\repo\bots\totembots`. Если папку перенести, ярлык нужно создать заново.

Если программа не запускается (например, после переноса папки или удаления `node_modules`), в PowerShell:

```
cd C:\Users\admin\claude-spaces\totemcraft_server\repo\bots\totembots; npm install; npm start
```

Нужен Node.js 22 или новее (https://nodejs.org).

### Первый запуск

1. «Войти через Chrome» - войти в Qwen через Google в открывшемся Chrome; окно закроется само.
2. «Настройки»: адрес и порт сервера, хозяева (первый - вы), год рождения (им программа отвечает на окно возраста Qwen),
   режимы Qwen. Сохранить.
3. Бот Alex уже добавлен. «Запустить».

Где что лежит на компьютере (не в git, там пароли ботов):
- `%APPDATA%\totembots\config.json` - настройки, боты и их пароли AuthMe, чаты Qwen;
- `%APPDATA%\totembots\memory\totemcraft.json` - резервная копия памяти (основная - в проекте Qwen «TotemCraft · боты»);
- `%APPDATA%\totembots\piper\` - Piper и голоса, если скачаны.

## Если Claude недоступен: как продолжать с Qwen, DeepSeek и т.п.

Эти нейросети не видят ваш компьютер и не помнят проект. Им нужно каждый раз показать, что это за программа
и какой файл менять. Порядок:

1. Новый чат. Первым сообщением вставьте целиком `README.md` и `DESIGN.md` из этой папки (это описание и план).
2. Вторым - файл, который нужно поменять (список ниже), целиком. Не больше одного-двух файлов за раз:
   слабые нейросети путаются в больших объёмах.
3. Просьба (шаблон ниже). Просите **файл целиком**, а не кусочки: так проще заменить и меньше ошибок.
4. Замените файл, запустите программу, проверьте. Если сломалось - покажите нейросети текст ошибки (журнал бота
   в панели или окно ошибки) и тот же файл.
5. Перед правкой сделайте копию файла (например, `bot.js` → `bot.js.bak`), чтобы можно было вернуть.

### Шаблон просьбы

```
Ты помогаешь дописывать программу TotemBots (описание и план выше). Вот файл app/<имя>.js целиком.
Задача: <что нужно, простыми словами, с примером>.
Правила проекта: бот не ломает чужие постройки (ломает только урожай и сразу сажает обратно), не читерит
(никаких полётов, скорости и т.п. - сервер ванильный, есть античит Vulcan), не врёт на прямой вопрос «ты бот?»,
без флирта, вещи из сундуков берёт только по приказу хозяев.
Верни файл целиком, без сокращений «...остальное без изменений». Комментарии в коде по-русски.
Кратко перечисли, что изменил и как проверить.
```

### Какой файл за что отвечает

| Файл | Что внутри | Когда трогать |
|---|---|---|
| `app/main.js` | окно, панель, настройки, запуск ботов, связь всех частей | новая кнопка или настройка |
| `app/panel.html`, `app/panel.js`, `app/panel-preload.js` | панель слева: кнопки, поля, журнал | внешний вид панели |
| `app/bot.js` | тело бота: вход на сервер, ходьба, сундуки, урожай, порталы, переподключение | новое умение в игре |
| `app/guard.js` | бой с мобами, броня, тотем | поведение в бою |
| `app/brain.js` | вводная для Qwen, разбор ответа, кто может приказывать, свобода воли (`ideas`), что слать в Qwen (`stateFor`, `look`) | характер, правила, новые команды для Qwen |
| `app/memory.js` | память: места, люди, факты, дневник | что и как запоминает |
| `app/qwen-bridge.js` | работа с окном Qwen: отправка, ответ, озвучка, окно возраста, два варианта ответа | если Qwen поменял сайт и что-то перестало работать |
| `app/qwen-project.js` | проект Qwen: создание, файл памяти | то же |
| `app/voice.js` | голос: Qwen, Piper, Windows | голос |
| `app/chrome-login.js` | вход в Qwen через Chrome | если перестал работать вход |

Новое умение обычно требует двух правок: в `bot.js` (само действие, в `run()` новый `case`) и в `brain.js`
(описание действия во вводной, чтобы Qwen знал о нём). Если действие трогает чужие вещи - его нет в списке `FREE`
в `brain.js`, и его выполняют только по приказу хозяев.

### Подводные камни (найдены при разработке, их легко сломать)

- Сервер 26.3, бот заходит клиентом 1.21.11 через ViaVersion. Бот обязан слать пакет `tick_end` каждый тик
  (`bot.js`, `loops()`), иначе сервер не видит его шагов.
- Вход AuthMe - окно до входа в мир; ответ собирается вручную (`clickActionPacket` в `bot.js`). Регистрация в игре
  выключена: аккаунт боту заводит администратор командой `authme register <ник> <пароль>` в консоли сервера.
- Античит Vulcan (стенд 15.11, отметки ушли с 36 до 0): удар только синхронно внутри тика и после того, как прицел
  был на цели (`guard.js`, `combatTick`); поворот плавный; отбрасывание - скорость из пакета без деления на 8000
  (`bot.js`, `entity_velocity`); урожай ломается одним «начал ломать» (`breakInstant`), без «закончил»;
  повторная смена слота на тот же не отправляется. Отладка: `TB_PACKETLOG=1` печатает последние пакеты при кике.
  Считая отметки на стенде, помнить: время в журнале стенда - UTC.
- Новый чат Qwen на миг получает адрес `/c/new-chat`: номер чата - только UUID (`currentChat` в `qwen-bridge.js`).
  После ошибки Qwen чат перезагружается (иначе PARENT_NOT_FOUND на всё следующее), сообщения повторяются один раз.
  Если Qwen оборвал ответ («Failed to fetch»), недописанный ответ навсегда запирает чат (`CHAT_IN_PROGRESS`, кнопка
  «стоп» `/api/v2/chat/completions/stop` не помогает, 15.11): после второго такого ответа бот начинает новый чат.
- Анти-иксрей Paper на сервере шлёт боту поддельные руды и сундуки внутри камня ниже y 64: карта и поиск считают
  их только открытыми (`XRAY_HIDDEN` в `worldmap.js`; список как hidden-blocks сервера).
- Вход в портал: только шагами pathfinder (`portal` в `bot.js`). Частые ручные прыжки в раму - Vulcan Step C, бан.
- Сторож застревания не должен вызывать `setGoal` (обрывает `goto`: «goal was changed»): он делает `setMovements`.
- На стенде `tp` перехватывает Essentials (меняет только координаты): в тестах `minecraft:tp`. Сложность по мирам:
  для Незера отдельно `execute in minecraft:the_nether run difficulty peaceful`.
- Два окна Qwen в одной сессии (`persist:qwen`): окно бота (`qwen`, мост) и окно владельца (`mine`). Показанное лежит
  сверху, второе работает (`backgroundThrottling: false`). В окно бота из панели не грузить ничего, пока мост занят.
- Ответ Qwen: реплика текстом, затем блок кода с `{"actions": [...]}`. Блок кода озвучка не читает.
- Сайт Qwen меняется. Если перестало работать «отправить», «прочитать вслух», выбор режима или проект -
  чинить в `qwen-bridge.js` / `qwen-project.js`: там названия кнопок и классов страницы (`textarea.message-input-textarea`,
  `button.send-button`, `[aria-label="More actions"]`, «Read aloud», «Edit Project», «Add Files», «Save»).
- Тесты (`test/`) работают только со своими настройками в `test/.data` и на тестовом сервере (Docker `tc-up`,
  порт 25566). На настоящем сервере тесты не запускать.

## Сервер

Чтобы бот вошёл на настоящий сервер: аккаунт в AuthMe (`authme register Alex <пароль>`, пароль - из
`config.json`), обход античита Vulcan для бота (права LuckPerms), доступ к сундукам LWC, если он носит ваши вещи.
Это делает администратор сервера; без этого бота выкинет или он не войдёт.
