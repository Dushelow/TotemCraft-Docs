# TotemBots: разбор архитектуры (22.11.2026)

Зачем: за день много жалоб «тупит, стоит, тонет, не садится, не слышит» чинились по одной, и каждый раз находилась
новая. Здесь - как устроена программа, какие корневые причины за этим стояли и какие правила из этого следуют.

## Как устроено

```
 Сервер Minecraft 26.3  <-- ViaVersion -->  бот (mineflayer 1.21.11)
                                              |
                тело (bot.js + модули)        |  каждый такт физики: tick_end, взгляд, бой, плавание, клик
                  - навигация nav.js (A* модуля пути + свои ходы: двери, люки, прыжки, плавание, лианы)
                  - вода swim.js / water.js, езда vehicles.js, зоны zones.js, компаньон companion/presence
                  - журнал движения movetrace.js, журнал страницы Qwen (qwen-bridge plog)
                                              |  события, итоги, состояние (текстом)
                мозг (brain.js)  --> маршрутизатор router.js --> сайт Qwen в окне Electron (qwen-bridge.js)
                  - вводная (warmText), сообщение = событие + [задача] + состояние
                  - быстрые приказы (quickOrder) - сразу телу, без нейросети
                                              |
                панель (panel.js/html) - карточки ботов, карта, «Жизнь», настройки, «Данные ботов»
                память: у каждого бота своя (memory/totemcraft-<ник>.json); общая только карта мира, тропы
```

Главный принцип: **тело делает, мозг решает**. Всё, что можно сделать без нейросети (ходьба, плавание, езда, простые
приказы, держаться на воде, уйти из огня), делает тело - быстро и предсказуемо. Нейросеть - для целей и разговора.

## Корневые причины за сегодняшними жалобами

| Жалоба | Корень | Где исправлено |
|---|---|---|
| Всё тормозит, бот «переподключается», проект Qwen сам открывается | работали **две копии программы** (после сброса с перезапуском): два Loki выбивали друг друга с сервера каждые 20-30 с, вторая копия синхронизировала проект в своём окне | main.js: одна копия на компьютер |
| Лодка стоит | пока бот едет, **физика mineflayer выключена целиком**: нет движения лодки (его делает водитель у себя) и нет «конца такта» | vehicles.js: rideTick как в клиенте |
| Не садится в лодку, жители не торгуют | клик по существу шёл **не как у клиента** (без interact_at, вне такта) | vehicles.js interactEntity |
| Плавает только по поверхности | модуль пути **«dont go underwater»** | nav.js swimMoves |
| Не лезет по лианам | в модуле пути **лианы не лестница** (строка закомментирована) | nav.js install |
| Тонет у борта и под лодкой | держаться на воде умел только в пути; **лодка над головой** не видна в блоках | swim.js floatTick, airTick |
| Банит античит | скорость тела в воде **задавалась напрямую** | swim.js: только клавиши + физика пловца |
| Не слышит хозяина | ближний чат хозяина классифицировался как «вокруг» | attention.js |
| Пишет без команд / «записал», а в игре нет | проверка «текст без команды» **стояла внутри «если команды есть»**; несказанное не возвращалось мозгу | brain.js, [не ушло в чат] |
| «База» на дне, «ловушки» на спавне | мозг сам записывал «базу» где стоял (под водой); реплика «руины» по ложной находке карты в городе | bot.js remember, mood.js |
| Зоны за смерть | смерть по своей ошибке считалась опасностью | zones.js по причине смерти |

Общий корень большинства: **мы не видели, что происходит**, и чинили по догадке. Теперь есть журнал движения
(`<бот>.move.log`, снимки случаев) и журнал страницы Qwen (`qwen-page.log`) - сначала смотреть их.

## Правила, которые из этого следуют

1. **Сначала журнал, потом правка.** Каждая жалоба - время, `move.log`/`qwen-page.log`, корень, правка, проверка на модели.
2. **Как настоящий клиент.** Всё, что уходит на сервер (движение, клики, езда), - так же, как делает игра игрока:
   клавиши и физика, в такт, с «концом такта». Своя скорость тела запрещена (античит).
3. **Одна копия программы**, одно окно Qwen, одна очередь запросов к нему (`bridge.exclusive`). Ничто не открывает
   страницы Qwen «само», кроме запросов мозга.
4. **Мозг не угадывает факты.** Координаты, места, пол людей - только из данных; не знает - спрашивает.
5. **Тело сообщает правду мозгу**: что не ушло в чат, что не получилось и почему.
6. **Проверка на модели** для каждой механики (test/*): вода, лианы, лодка, зоны, приказы. Долгие прогоны - по просьбе.

## Что ещё слабо (следующие шаги)

- Лодка (поставить, плыть, встать у стены, слезть) и торговля (одиночный житель, ячейка трейдхолла) проверены
  на стенде 23.11, античит молчит. Подробно - `STABILITY_REPORT.md`, каталог механик и пробелов - `MECHANICS.md`.
- Понимание сложных заданий нейросетью (метро, поиск пути через незерхаб) - слабое место самой модели; помогает
  [задача] и примеры во вводной, но нужен разбор на живых случаях.
- Переход на 26.3 без ViaVersion (форк данных протокола) - отложен владельцем.
